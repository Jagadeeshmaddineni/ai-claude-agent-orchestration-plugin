# SS&C Codebase Graph Analyzer

> Inherited from [code-review-graph](https://github.com/tirth8205/code-review-graph) and adapted for the Codebase analysis accelerator domain.

Token-efficient codebase analysis and code review using a persistent knowledge graph.

---

## Overview

The **SS&C Codebase Graph Analyzer** plugin brings graph-powered, token-efficient code review and codebase navigation to Claude Code. It parses your repository with Tree-sitter, stores a structural knowledge graph in SQLite, and exposes it via MCP tools so Claude reads only the code that matters — not the entire codebase.

**Key benefit:** 5-10x token reduction on code review tasks by using blast-radius analysis instead of full-file scanning.

## How It Works

Your repository is parsed into an AST with Tree-sitter, stored as a graph of nodes (functions, classes, imports) and edges (calls, inheritance, test coverage), then queried at review time to compute the minimal set of files Claude needs to read.

**Supported languages:** Python, TypeScript/JavaScript, Vue, Go, Rust, Java, Scala, C#, Ruby, Kotlin, Swift, PHP, Solidity, C/C++ (19 total)

### Automatic Graph Updates (Hooks)

The plugin installs two hooks:
- **SessionStart** — checks graph availability and injects MCP tool guidance
- **PostToolUse (Write/Edit/Bash)** — incrementally updates the graph after every file change (< 2 seconds)
- **PostToolUse (EnterWorktree)** — triggers a full background build when switching worktrees

## MCP Tools Reference

The `code-review-graph` MCP server exposes 22 tools. Key ones used by this plugin:

| Tool | Use when |
|------|----------|
| `detect_changes` | Reviewing code changes — gives risk-scored analysis |
| `get_review_context` | Need source snippets for review — token-efficient |
| `get_impact_radius` | Understanding blast radius of a change |
| `get_affected_flows` | Finding which execution paths are impacted |
| `query_graph` | Tracing callers, callees, imports, tests, dependencies |
| `semantic_search_nodes` | Finding functions/classes by name or keyword |
| `get_architecture_overview` | Understanding high-level codebase structure |
| `refactor_tool` | Planning renames, finding dead code |
| `build_or_update_graph_tool` | Building or incrementally updating the graph |

### Token Efficiency Rules

All skills follow this protocol:
1. Always start with `get_minimal_context(task="<description>")` — ~100 tokens, full picture
2. Use `detail_level="minimal"` on all subsequent calls
3. Target: ≤5 tool calls, ≤800 total graph context tokens per task

## Graph Storage

The knowledge graph is stored at `.code-review-graph/graph.db` (SQLite, WAL mode) in your repo root. Add `.code-review-graph/` to `.gitignore` — it's a local build artifact.

```bash
echo ".code-review-graph/" >> .gitignore
```

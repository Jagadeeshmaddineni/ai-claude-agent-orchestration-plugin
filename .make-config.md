# Make Configuration

## Issue Tracker

<!-- Which issue-tracker backend to use: jira, github, or none -->
tracker: jira

Selects the issue-tracker backend for `/make`, `/build`, `/make-clean`, and the
work queue. The rest of the workflow is identical regardless of backend — this is
the single switch that lets a repo swap trackers.

- `jira` -- Jira backend. Cache context with `/agent-orch:jira` (`.claude/rules/jira.md`).
- `github` -- GitHub Issues on `code.ssnc.dev` via `gh`. Cache with
  `/agent-orch:github-issues` (`.claude/rules/github.md`).
- `none` -- no issue tracker (skip all tracker steps).

> **Back-compat**: if `tracker:` is absent, the legacy `jira_mode:` below is used
> (`yes`/`ask-me` ⇒ jira, `no` ⇒ none). For a finer-grained override, set
> `tracker.provider` in `.claude/ssnc-agent-orch/tracker.yaml`. Full contract:
> `plugins/agent-orch/rules/tracker-provider.md`.

## Jira Integration

<!-- Change this value to: yes, no, or ask-me -->
jira_mode: yes

## How to Change

Edit the `jira_mode` line above (applies when `tracker: jira`):
- `yes` -- always require an issue (you can opt out per-session)
- `no` -- never use a tracker
- `ask-me` -- prompt each time (includes "skip" option)

## Prerequisites

When using `tracker: jira` (jira_mode `yes` or `ask-me`), ensure:
1. MCP server is running: `/agent-orch:mcp-start`
2. Jira context is cached: `/agent-orch:jira`
3. `.claude/rules/jira.md` exists with project metadata

When using `tracker: github`, ensure:
1. `gh` is authenticated for the Enterprise host:
   `GH_HOST=code.ssnc.dev gh auth login`
2. GitHub context is cached: `/agent-orch:github-issues`
3. `.claude/rules/github.md` exists with repo metadata
